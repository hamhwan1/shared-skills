# Record a service demo

1. Inspect the actual target service and any requested reference video. For video style references, watch the requested interval and record observed pacing, framing and cursor treatment; disclose if playback is unavailable. Do not invent observations or claim professional quality without visual review.
2. Check Node, Playwright, Chrome and FFmpeg. Install project dependencies with `npm.cmd install playwright ffmpeg-static`. Check the execution process network separately from the user's browser. On failure, distinguish DNS lookup, TCP and HTTP errors; do not repeat unchanged diagnostics. Report the exact blocker. Use the user's ordinary terminal for user-run scripts when this execution environment cannot connect; never silently change security policy.
3. Read only the project root `.env` for ELEVENLABS_API_KEY and ELEVENLABS_VOICE_ID. Never print or embed secrets. Provide `.env.example` when missing. Test parsed nonempty values, not a whitespace regex that can cross lines.
4. For authenticated services, use `scripts/record.cjs` with `--login`. Let the user sign in manually in a dedicated browser profile. Do not capture credentials or ask for passwords in chat. Start capture only after explicit login completion. Keep session profiles and all live page evidence local and out of Git.
5. Inspect `inspection.json` and `inspection.png`; select a safe demo folder with no customer information. Write a concise plan containing verified selectors and actions. Use no destructive actions, real uploads, shares or invitations unless specifically authorized. Do not guess selectors. Create `capture-plan.json` in the output directory when ready.
6. Design a 20-second story: 0-4s value, 4-10s first workflow, 10-16s second workflow, 16-20s result. Keep movement and action timing within the available duration. Use `human.cjs` for curved cursor travel, visible pointer, click rings, character-by-character typing with 100-200ms delay, smooth scrolling and target-centered zoom. Keep captured site content intact.
7. Run `node skills/record-service-demo/scripts/record.cjs URL --login` from the project root. The browser stays open after inspection until the capture plan is supplied. For public pages, omit --login. This records actual changing browser frames and uses measured capture times for MP4 encoding; do not describe static mockups as screen recordings. Check capture cadence and motion smoothness; use CDP screencasting or native recording for denser footage if screenshot cadence is inadequate.
8. Write `narration-script.json` in the recording directory: `{ "scenes": [{ "start": 0.5, "end": 5, "text": "Verified Korean narration" }] }`. Cover 0.5-19.5s with contiguous scenes. Run `node skills/record-service-demo/scripts/finish.cjs OUTPUT_DIRECTORY`. It loads the project .env, generates per-scene audio, aligns speech and subtitles, and encodes 20s H.264/AAC MP4. Check scene duration before generating; avoid clipped speech. Cached audio must be invalidated when text, voice or model changes.
9. Verify resolution, 20s duration, video/audio streams, decode, audible levels, subtitle legibility, personal-data absence and speech/visual timing. Render sample frames and listen to the output when supported; otherwise state exactly what remains user-reviewed. Technical decode alone is not visual or listening QA.
10. Deliver MP4, runnable scripts, narration/subtitle files and concise validation results. Distinguish created files, installed/discoverable skill status, and GitHub push success. Publish only a whitelist of skill files; exclude .env, browser profiles, session state, recordings, screenshots, logs and node_modules. Preserve unrelated repository files.
